# audiobookshelf rules

- abs_check_references: consult the official Audiobookshelf implementation to match API behavior (https://github.com/advplyr/audiobookshelf).
  - Verify: cite the ABS source or documented behavior in the change notes for every ABS endpoint, scanner, or metadata behavior change.
- abs_api: the ABS-compatible API in `src/audiobookshelf/` serves audiobook libraries and items as books, including library browsing, item detail, covers, and playback/progress. Use `abs_check_references` when adding or changing ABS endpoints.
  - Verify: the affected routes and prefix aliases are exercised by `tests/unit/abs_endpoints.rs`.
- directory_structure: book library scanning follows the ABS directory structure (https://audiobookshelf.org/docs/documentation/libraries/book-library/directory-structure). Items are `{Author}/{Series}/{Book}`, `{Author}/{Book}`, or a book folder at the library root; standalone audio files at the root are single-file books; `Disc`/`CD`/`Disk` subfolders belong to the parent book. Folder names populate title, author, series sequence, publish year, narrator, and ASIN. `src/audiobookshelf/scanner.rs` owns this grouping and parsing.
  - Verify: scanner tests cover root single-file books, author-only books, `Author/Book`, `Author/Series/Book`, disc subfolders, and the documented folder-name forms for year, sequence, narrator, ASIN, and subtitles.
- metadata_matching: when a book item has no stored metadata, library scanning matches it against the same source set Audiobookshelf uses: Audible/Audnexus first, then iTunes, Google Books, OpenLibrary, and FantLab, with AudiobookCovers as a cover fallback. A book card/detail also offers manual matching with a provider choice, which may override stored metadata and the cover. Matched ABS metadata and artwork belong in the item sidecar `.hbgr` (or the config `.hbgr` directory in config mode). Automatic matching must never overwrite existing stored metadata or a user-selected cover.
  - Verify: an audio-only book gains `.hbgr/metadata.json` and a cover after a matching scan; a book with existing metadata or a custom cover is left unchanged by automatic matching; the manual dialog exposes Audible, iTunes, Google Books, OpenLibrary, and FantLab and selecting a match replaces the metadata and cover.
- cover_precedence: resolve book covers in this order: the `cover` reference in stored metadata, any existing stored `.hbgr` cover image, embedded cover art from the audio file, `cover.<image ext>`, the book/media filename with an image extension, then any image in the item directory. Store extracted and selected covers under `.hbgr` in media mode and under the config directory in config mode; config mode must not write to the media folder.
  - Verify: tests prove each fallback in order, embedded-cover extraction from a real tagged audio file, and that config-mode cover changes leave the media folder unchanged.
- book_card_layout: book cards keep the shared media card but use a square cover.
  - Verify: rendered book cards carry `media-card-book`, and only that card class is styled with `aspect-ratio: 1/1`.
- book_read_state: book actions use read/unread wording (`Mark as read` / `Mark as unread`) and a read book shows a checkmark badge, matching the TV watched-state presentation.
  - Verify: book card menus render the read/unread labels, and a read book renders a `✓` badge with the accessible label `Read`.
- book_cover_upload: the book cover dialog offers stored `.hbgr` images, the embedded cover, every image in the book folder, a URL download, and a local file upload. Selecting any source copies it to `.hbgr/cover.<ext>`, writes the `cover` reference into `metadata.json`, and follows `cover_precedence` storage rules.
  - Verify: the dialog lists each source, selecting any source changes the served cover, URL covers are downloaded rather than referenced remotely, `metadata.json` records the cover filename, and config mode writes no cover into the media folder.
